# Adding and maintaining resources

Choose the topic that best describes the learning outcome. Create a descriptive lowercase folder name under tutorials/. Record teaching years inside the README rather than in folder names.

Each resource needs a README.md covering:
- Learning outcomes.
- Software, tested versions and required packages.
- Prerequisites and difficulty.
- Author, original teaching year and last verified date, where known.
- Instructions or a link to a notebook/PDF.
- Example files, data sources and credits.

For new tutorials, use images/ for illustrations and examples/ for runnable projects. Keep dependent assets together. Existing projects retain their internal layouts to preserve references.

Add links to the topic README and relevant software indexes. Link across topics when useful; keep one authoritative copy.

Check image links and run example projects before marking compatibility as verified. Keep software backups, temporary files and unnecessary render sequences out of future commits. Review existing supporting files before removing them.

Publish only material you have permission to share and document third-party data and asset licences separately.
